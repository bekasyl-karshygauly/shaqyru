# Публикация копии из трёх папок

1. Загрузить в корень GitHub по очереди папки `server`, `public`, `assets` ЦЕЛИКОМ.
   После каждой части нажать Commit changes. Не загружать все три части разом:
   у GitHub есть ограничение 100 файлов за одну загрузку.
2. Подключить репозиторий к Render как Blueprint. Blueprint Path: `server/render.yaml`.
   Указанный план free предназначен для предварительного запуска; он засыпает при простое.
3. В секретах Render задать SUPABASE_SERVICE_KEY и SUPABASE_ANON_KEY.
   ADMIN_KEY можно задать выбранным владельцем значением: иначе Blueprint создаст новый ключ.
   Секретные значения не сохранять в GitHub. Оплата согласуется лично, ключи оплаты не нужны.
4. Render выдаст публичный HTTPS-адрес. Приложение использует RENDER_EXTERNAL_URL автоматически.
5. Настроить адрес сайта и шаблоны писем для входа по коду, затем проверить вход.
   Шаблон письма: `server/supabase/templates/email-code.html`.
6. Проверить публичный сайт: создание приглашения, заявку, одобрение через /admin,
   открытие гостевой ссылки, анимации и RSVP. Отдельно проверить реальные телефоны.

Dockerfile: `server/Dockerfile`; контекст сборки: корень репозитория.
Контейнер восстанавливает исходные пути приложения, поэтому сайт использует
те же URL и серверные модули, что и рабочая локальная версия.

Документация: https://render.com/docs/blueprint-spec
