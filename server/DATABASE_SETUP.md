## Применено 19 октября 2026

После явного подтверждения пользователя успешно применена миграция `complete_shaqyru_server_schema`. Все 17 приглашений сохранены; гостей по-прежнему 0.

Применены существующие файлы `migrations/001_payments.sql`, `002_guest_index.sql`, `003_accounts.sql`, `004_rsvp_details.sql` в одной миграции:

- Создать журнал `shq_payments` и функцию подтверждения платежей. Функция работает с правами вызывающего (`SECURITY INVOKER`), доступна только серверной роли. Само создание таблицы не включает приём платежей.
- Создать закрытую таблицу `shq_cloud_drafts` для облачных черновиков.
- Добавить `details` к ответам гостей и индекс поиска гостей приглашения.
- Оставить RLS включённым и запретить прямой доступ браузерных ролей к рабочим таблицам. Сервер проверяет владельца перед доступом.
- Создать публичный bucket `shaqyru-audio` для загруженной музыки (до 15 МБ). Аудио будет доступно всем, у кого есть ссылка; права прямой загрузки браузеру не выдаются.

Существующие записи не удаляются и не переписываются. Старые таблицы `invitations` и `guests` не затрагиваются.

## Проверки после применения

SQL-проверка подтвердила таблицы, индексы, поле details, RLS и права функции. REST вернул HTTP 200 серверному ключу и HTTP 401 публичному ключу для всех четырёх рабочих таблиц (limit=0, без чтения пользовательских данных).

Supabase advisors не обнаружил предупреждений или ошибок безопасности. Информационные сообщения RLS Enabled No Policy ожидаемы для рабочих таблиц: доступ идёт через сервер, браузерные роли доступа не имеют. Старые таблицы invitations и guests не изменялись. Описание: https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy

В локальном .env настроены SUPABASE_ANON_KEY и PUBLIC_URL=http://localhost:3108. Проверка account:check прошла: облачная таблица доступна, Auth принимает ключ. Доставка кода входа требует отдельной проверки email/SMTP; письма не отправлялись. Секреты платежного провайдера подключаются отдельно. Для публикации нужно заменить PUBLIC_URL на рабочий HTTPS-адрес.
