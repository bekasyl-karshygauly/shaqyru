Оригинал обрабатывается в браузере, без загрузки на сторонние сервисы.

Основной новый модуль: `public/editor-assistant.js`; подключение: `public/index.html`; оформление: `public/style.css`. Проверки: `tests/editor-assistant.test.js` и `tests/browser/assistant.spec.js`. ## P0 — сохранение данных и доступ

- Исправлена гонка между сохранением текста и установкой пароля. У каждого документа есть версия; обновление выполняется одним условным запросом. Устаревшее сохранение получает 409, вместо удаления нового пароля или перезаписи текста другой вкладки. Это также защищает настройку закрытия приглашения. Файлы: `invitation-store.js`, `server.js`, `public/index.html`.
- При конфликте редактор сохраняет локальные изменения, предлагает скачать черновик и загрузить актуальный документ. Перед загрузкой создаётся локальная резервная копия `shq-recovery`. Старый браузерный черновик не перезаписывает более свежую серверную версию автоматически.
- Формат гостевого токена проверяется целиком. Новые приглашения получают 128-битные случайные идентификаторы, персональные ссылки — 96-битные коды. Старые ссылки продолжают поддерживаться. Файлы: `invitation-access.js`, `server.js`, `scripts/cleanup-audio.js`, `public/index.html`.
- Сохранена обязательная проверка подписанного подтверждения реального списания через журнал платежей. Несуществующая карта, локальный флаг оплаты, возврат с платёжной страницы и прежнее значение `paid` не открывают приглашение. При отсутствии настройки продавца оплата недоступна. Проверка готовности теперь учитывает доступность таблицы платежей.

## P1 — работа редактора и гостей

- Разделены лимиты обычного сохранения, установки пароля, разблокировки, ответов, загрузок и других действий. Десять сохранений больше не расходуют лимит установки пароля. Превышение лимита сопровождается `Retry-After`. Проверка проходит до разбора тела запроса. Файлы: `rate-limits.js`, `server.js`.
- Для обычных API действует лимит JSON 64 КБ. Для приглашений с существующими встроенными фотографиями и загрузки музыки сохранены отдельные большие лимиты. Ошибки входных данных и превышения размера возвращаются понятным ответом.
- Повторная отправка ответа по общей ссылке обновляет одну запись, используя стабильный идентификатор запроса и существующий уникальный код гостя. Тест проверяет как повтор, так и изменение ответа. Это защита от повторной отправки в одном браузере, а не глобальная идентификация людей. Файлы: `server.js`, `public/event-tools.js`, `public/view.html`.
- Исправлены обрезанные поля и горизонтальный выход за экран на телефонах. Длинные имена переносятся, полная карточка растёт по высоте. Проверены ширины 320, 390, 768, 1024 и 1440 пикселей. Файлы: `public/style.css`, `public/index.html`.
- Выбранный эффект действительно применяется к карточке, включая сердца. Системное уменьшение движения останавливает эффекты CSS и canvas. Вступительный экран поддерживает Escape, удержание фокуса и возврат к кнопке запуска. Музыка управляется настоящей кнопкой с клавиатуры. Файлы: `public/card.js`, `public/style.css`, `public/view.html`.
- Поля получили связанные подписи; добавлены видимый фокус, сообщения состояния и правильный язык документа на казахской странице. Доработана локализация подписей. Файлы: `public/index.html`, `public/view.html`, `public/i18n.js`.
- При отказе гостя больше не показывается «Ждём вас». Копирование ссылки показывает успех только после успешного завершения; отказ браузера сопровождается сообщением.

## P2 — скорость, сопровождение и индексация

- Созданы WebP-обложки и маленькие превью без удаления оригиналов: оригинальные JPEG — 8 685 016 байт, все полноразмерные WebP — 2 035 492 байта, все миниатюры — 301 156 байт. Полный комплект обложек уменьшен на 76,6%. Это сравнение файлов, а не обещание такого же ускорения загрузки страницы.
- Галерея использует отложенную загрузку миниатюр и кеширует повторный рендер. При сбое загрузки оптимизированного изображения предусмотрен переход к оригиналу. Команда `npm run assets:build` воспроизводит генерацию существующей библиотекой. - Список администратора получает подтверждения оплат пачкой. В тесте 100 приглашений требуют двух запросов к базе вместо 101; при большем журнале предусмотрены страницы. Файл: `server.js`.

- Подготовлен индекс списка гостей в `migrations/002_guest_index.sql`. Он не применялся. В Docker-рецепт добавлен шрифт для серверных изображений; сборка Docker здесь не проверялась.
- Добавлены проверка синтаксиса и регрессионные тесты. Обновлены инструкции запуска и сохранения в `README.md`.

## Что осталось перед рабочим запуском

1. Подключить кабинет продавца, HTTPS и параметры Freedom Pay, проверить миграцию `001_payments.sql` в тестовой базе и провести согласованный реальный платёж. Сейчас рабочий эквайринг отсутствует; при прежней проверке таблица платежей была недоступна. Обход этого ограничения не добавлялся.
2. Владелец должен отозвать ранее раскрытые ключи в кабинете Supabase и проверить старые архивы. Удаление ключей из примера конфигурации не подтверждает их отзыв.
3. Проверить миграции, ограничения и RLS в отдельной базе, резервное копирование и восстановление. Здесь нет отдельного тестового PostgreSQL и доступа к настройкам аккаунта.
4. Проверить размещение, Docker-сборку, HTTPS, кеширование публичных ресурсов и реальные показатели скорости. Лимитер хранится в памяти одного процесса; для нескольких серверов нужен общий лимитер.
5. Дальнейшие улучшения: уменьшить дублирующие запросы гостевой страницы и метаданных, дополнить обработку повреждённых загружаемых фотографий, проверить казахские тексты с носителем языка и реальные Safari/Firefox. Архитектура с большими встроенными скриптами сохранена; её постепенное разделение требует отдельной задачи.

## Мои возможности и ограничения

Самостоятельно изучены исходники, реализованы исправления, подготовлены изображения, документация и тесты. Для проверки использованы Node.js, Chromium/Playwright, Git, существующая библиотека canvas и один безопасный запрос к Supabase. Браузер позволяет проверять реальные размеры, фокус, анимации и действия; одних исходников для этого недостаточно.

Не выполнены подключение эквайринга, отзыв ключей, производственное развёртывание, рабочие SQL-миграции и проверка реального платежа: они требуют кабинетов владельца и отдельной проверенной среды. Доступ к серверу нужен для HTTPS, эксплуатации и мониторинга; доступ к тестовой базе — для независимой проверки SQL и RLS. Наиболее сложная исправленная проблема — согласованное сохранение текста и приватных настроек при конкурирующих вкладках без обязательной новой миграции.

Дополнительные инструменты и разрешения позволят провести тесты Safari/Firefox и реальных устройств, SQL-тесты конкурентности, нагрузочную проверку и наблюдение за рабочей системой. Полная готовность к коммерческому запуску пока не заявляется.
