# Уведомления о заявках

Заявки сохраняются в кабинете и ждут ручного одобрения. Цены существующих уровней: 2 490 / 3 990 / 5 990 / 8 990 ₸. Онлайн-оплата отключена.

В сообщение WhatsApp/Telegram включена ссылка `/admin#order=ID`: после ввода ключа открывается приглашение клиента с анимацией и кнопкой публикации. Сама ссылка не даёт прав администратора. На localhost она работает только на компьютере с сервером; для телефона и клиентов нужен опубликованный сайт с HTTPS.

## Текущее состояние

Серверная отправка реализована. На проект shaqyru применена миграция `20261019155210_order_notification_outbox.sql`. У владельца есть приложение WhatsApp Business на телефоне. Подключения Telegram Bot API и WhatsApp Cloud API ещё не настроены, поэтому реальная автоматическая отправка **не включена**. Статус подключений виден в кабинете → «Уведомления о заказах». Секреты туда не выводятся.

## Telegram

Можно использовать прежний токен BotFather, пока он не отозван. Владелец подтвердил, что прежний проект остановлен. Секрет не передаётся в чат, браузер или репозиторий.

1. В терминале из папки проекта запустить `npm run telegram:connect -- --pair`.
2. Вставить токен BotFather в скрытый ввод. До ввода токена программа не обращается к Telegram. Если токен уже сохранён в серверном `.env`, используется он.
3. Открыть показанную ссылку со своего Telegram-аккаунта и нажать «Запустить» в течение двух минут. Случайный одноразовый код связывает только подтверждённый личный чат; чужой `/start` не подходит.
4. Программа сохранит `TELEGRAM_BOT_TOKEN`, числовой `TELEGRAM_CHAT_ID` и `TELEGRAM_BOT_USERNAME` в локальном `.env`, сохраняя остальные настройки, и отправит тестовое сообщение. Реальный токен нигде не выводится. До завершения этих шагов бот не считается подключённым.
5. Перезапустить сервер. В кабинете → «Уведомления о заказах» доступна кнопка «Отправить тест в Telegram». Ответ «Telegram принял» означает приём API; сообщение нужно проверить в личном чате.
6. Для автоматической отправки рабочих заявок указать публичный HTTPS-адрес сайта в `PUBLIC_URL` и перезапустить сервер. На localhost доступен тест, но очередь заявок не отправляется с неработающими на телефоне ссылками.

Существующий webhook не удаляется и не меняется. Если он остался у прежнего проекта, программа объяснит причину и остановится: можно вручную задать уже известный числовой `TELEGRAM_CHAT_ID` или использовать отдельного бота. При готовом ID чата получение входящих сообщений вообще не используется. Режим `--pair` предназначен только для остановленного прежнего проекта: параллельный `getUpdates` работающего приложения может конфликтовать. Обычный тег @Bekasyl не заменяет числовой ID.

Кнопка теста требует действующего ключа администратора, ограничена тремя запросами в минуту и не принимает произвольного получателя. Настройки API показывают только наличие секретов и публичное имя бота. Старые ожидающие заявки после включения публичного адреса также попадут в обработку.

Уведомление содержит данные заявки и кнопку перехода в кабинет. Основано на [Telegram Bot API sendMessage](https://core.telegram.org/bots/api#sendmessage).

## WhatsApp

Нужен зарегистрированный отправитель [WhatsApp Cloud API](https://www.postman.com/meta/whatsapp-business-platform/documentation/wlk6lh4/whatsapp-cloud-api) и разрешённая отправка на номер владельца +77788562088. Номер отправителя настраивается отдельно; номер владельца — получатель уведомления.

В серверных секретах заполнить:

- `WHATSAPP_ACCESS_TOKEN` — токен приложения с доступом к отправке;
- `WHATSAPP_PHONE_NUMBER_ID` — ID номера отправителя;
- `WHATSAPP_API_VERSION` — поддерживаемую аккаунтом версию Graph API вида `vNN.N`;
- `WHATSAPP_ORDER_TEMPLATE` — имя утверждённого шаблона уведомления;
- `WHATSAPP_TEMPLATE_LANGUAGE` — код языка утверждённого шаблона.

Шаблон должен иметь ровно пять текстовых переменных в теле, в таком порядке:

1. ID заявки;
2. имена/название праздника;
3. стоимость;
4. телефон или email клиента;
5. ссылка на заявку в кабинете.

Пример тела шаблона: «Новая заявка {{1}}. Приглашение: {{2}}. Стоимость: {{3}}. Контакт: {{4}}. Посмотреть и согласовать: {{5}}». Шаблон и категорию утверждает Meta. Следовать актуальным условиям аккаунта и провайдера; сервис не подключён и платные ресурсы в этой работе не создавались. Формат запроса — [официальная коллекция Meta](https://www.postman.com/meta/whatsapp-business-platform/request/lwtlz1k/send-message-template-interactive).

## Очередь и ошибки

Триггер создаёт задания в той же транзакции, что и сохранение заявки. Обычное редактирование приглашения и публикация не создают лишних уведомлений. Повторная отправка/обновление заявки создаёт новое событие. Исторические заявки миграция не рассылает; ожидающие задания после подключения начнут обрабатываться, в том числе созданные до подключения.

Работающий Node-сервер обрабатывает очередь каждые 20 секунд, только для настроенных каналов и публичного HTTPS-адреса. На хостинге, который останавливает процесс при простое, доставка ожидает возобновления сервера. Записи переживают перезапуск. Захват заданий с `SKIP LOCKED` и временным уникальным lease защищает от параллельной отправки разными процессами. Временные ошибки повторяются с задержкой, максимум шесть попыток. Постоянные ошибки доступны в заявке с кнопкой повторной отправки после исправления настроек.

Статус «Принято сервисом» подтверждает ответ API, **не доставку/прочтение на устройстве**. При сетевом сбое после фактического принятия сообщения провайдером повтор может создать дубль: гарантия exactly-once не заявляется. Контакты и сырые ответы провайдеров не попадают в журнал ошибок; секреты остаются на сервере. Публикация выполняется только из кабинета с ключом и проверкой версии приглашения.

Проверки: `tests/order-notifications.test.js`, `tests/orders.test.js`, `tests/support-contacts.test.js`, `tests/browser/orders.spec.js`. На реальном Supabase проверены два задания на одну заявку, захват одного канала, отсутствие повторного захвата и отсутствие новых заданий при обычном редактировании; тестовая транзакция откатилась. Анонимный и обычный авторизованный пользователь не имеют SELECT к очереди. Реальная доставка пока не проверена — подключений нет.
