# Копия для загрузки трёх папок целиком

В корне репозитория должны быть три папки: `server`, `public`, `assets`.
Их имена и структуру менять не нужно.

Хостинг Render: Blueprint Path `server/render.yaml`.
Конфигурация уже использует Dockerfile `server/Dockerfile` и контекст корня репозитория.
Docker восстанавливает исходную структуру приложения, включая `/public/covers`.
Все существующие адреса страниц, ресурсов и API сохраняются.

Для локальной разработки: `cd server`, `npm ci`, скопировать `.env.example` в `.env`
и заполнить локальные настройки, затем `npm start`. Перед npm-командами скрипт
`prepare-upload-layout.js` автоматически собирает `server/public` и `server/tests`
из остальных двух папок. Это производные папки, они исключены из Git.
Настройки и секреты хостинга задаются отдельно; они не включены в эту копию.

# Шақыру

Рабочая модель: клиент отправляет заявку через «Согласовать заказ», организатор обсуждает стоимость и публикует приглашение в `/admin`. Автоматическое оформление платежей отключено. Инструкция: [MANUAL_ORDERS.md](MANUAL_ORDERS.md).

Цены дизайнов отображаются до отправки заявки. Серверная очередь уведомлений Telegram / WhatsApp Business и ссылка на конкретную заявку: [ORDER_NOTIFICATIONS.md](ORDER_NOTIFICATIONS.md). Реальная отправка требует подключений и публичного HTTPS-адреса; без них сообщения остаются в очереди.

Красивые постоянные ссылки по именам, например `/arman-aigerim`, выделяются при публикации. Прежние ссылки сохраняются. Подробности и миграция: [PRETTY_LINKS.md](PRETTY_LINKS.md). Подключение прежнего Telegram-бота со скрытым вводом токена: `npm run telegram:connect -- --pair`; этот режим предназначен для бота, который больше не работает в другом приложении. Проверка отправки доступна в кабинете организатора.

Золотые отражения, бумажная фактура и фоновый свет Three.js/GLSL связаны с прежними GSAP clocks без новых ScrollTrigger. Эффекты доступны в готовом приглашении и полном предпросмотре; HTML остаётся интерактивным, а отсутствие WebGL или снижение движения сохраняют прежнее оформление. Устройство слоёв, ограничения GPU и проверки: [WEBGL_EFFECTS.md](WEBGL_EFFECTS.md).

Проверка процесса заказа, красивых ссылок и кабинета без реальных писем, Telegram и Supabase: `npm run test:workflow`. Используется отдельная база в памяти на порту 3110. Для уже запущенного `node scripts/serve-workflow-fixture.js` можно указать `WORKFLOW_TEST_URL=http://127.0.0.1:3110`; в этом режиме тест не запускает и не останавливает сервер самостоятельно.

Статусы, услуги, правки, индивидуальная цена, подтверждение варианта, история, избранное, архив, статистика, отзывы и RSVP-уведомления: [ORDER_WORKFLOW.md](ORDER_WORKFLOW.md). Для новой базы также нужны миграции 003/004 и обе миграции с датой 20261019 из migrations/; в подключённом проекте shaqyru они уже применены.

Конструктор приглашений: 11 событий, 30 дизайнов, 18 обложек, русский и казахский текст, фотографии, музыка, анимации, программа, персональные ссылки и ответы гостей.

## Запуск

1. Установите Node.js 20.6 или новее.
2. Выполните `npm ci`.
3. Скопируйте `.env.example` в `.env` и заполните настройки Supabase. Используйте URL проекта без `/rest/v1` и серверный секретный ключ. Не публикуйте `.env`.
4. В Supabase → SQL Editor выполните `migrations/001_payments.sql`. Скрипт добавляет журнал платежей, серверную функцию подтверждения и хранилище музыки. Существующие приглашения сохраняются. Отключается прямой доступ к таблицам через публичные ключи.
5. Выполните `npm start` и откройте http://localhost:3000.

Черновик и предпросмотр работают без базы. Сохранение на сервере, загрузка музыки и работа с гостями требуют Supabase и миграции. До первого сохранения на сервере черновик хранится только в текущем браузере. После создания заказа изменения отправляются автоматически; ошибка сохранения видна в редакторе.

## Сохранённая интеграция оплаты для возможного будущего подключения

Этот раздел описывает прежнюю интеграцию. Сейчас создание платежей отключено в сервере; перечисленных настроек недостаточно для включения оплаты. Текущий процесс — ручное согласование и публикация по MANUAL_ORDERS.md.

Номер карты получателя не является подключением к интернет-эквайрингу. Зарегистрируйте продавца в Freedom Pay: https://freedompay.kz/ . Провайдер проверит продавца и выдаст настройки приёма оплаты на ваш счёт; требования и условия уточняются у провайдера.

1. Получите рабочие `FREEDOMPAY_MERCHANT_ID` и `FREEDOMPAY_SECRET_KEY` в кабинете продавца. Это должны быть настройки реального, а не тестового приёма оплаты.
2. Разместите сайт по публичному адресу с HTTPS и запишите этот адрес в `PUBLIC_URL`, например `https://invite.example.kz`.
3. Убедитесь, что `https://ваш-сайт/api/payments/result` доступен Freedom Pay без авторизации. Метод — POST. В кабинете при необходимости укажите этот адрес как Result URL.
4. Включите у провайдера одностадийную оплату / автоматическое списание (`pg_auto_clearing=1`). Сервер требует подписанного подтверждения фактического списания (`pg_captured=1`), а не только авторизации карты. Подтвердите настройки уведомлений с менеджером Freedom Pay.
5. Перезапустите сервер. Проверьте отмену платежа и затем проведите согласованный небольшой реальный платёж. Только после реального подтверждения можно считать интеграцию проверенной в рабочем кабинете.

Документация интеграции: https://freedompay.kz/docs-en/merchant-api/pay и https://freedompay.kz/docs-en/merchant-api/intro .

Реквизиты карты вводятся на странице провайдера. Этот сервер не принимает номер карты или CVV. Без настроек продавца кнопка оплаты отключена. Сам возврат на сайт, query-параметр `payment=return`, локальное `paid=1` и прежний флаг `paid` в базе не открывают доступ. Нужна запись в новом журнале, созданная после проверки подписи, номера заказа и платежа, суммы, валюты, рабочего режима и списания. Повторные уведомления обрабатываются без повторной активации. Ручная активация администратором отключена.

**Старые приглашения, активированные имитацией оплаты, теперь закрыты для гостей**, пока не будет подтверждён реальный платёж. Тестовые платежи намеренно не открывают рабочие приглашения. Нельзя вручную создавать `confirmed`-записи в журнале.

## Предпросмотр и восстановление редактора

Предпросмотр показывает карточку сразу. Анимация запускается отдельной кнопкой. Он хранится временно в браузере владельца и не является ссылкой для гостей; печать и ответы в нём недоступны, есть отметка ПРЕВЬЮ. Гостевые ссылки имеют вид `/i/ID` или `/i/ID?g=КОД` и проверяются сервером.

Для восстановления редактора на другом устройстве используйте `/#id=ID&t=ТОКЕН`. Секрет владельца нельзя передавать гостям. Старые ссылки с query-токеном понимаются редактором, после чтения токен убирается из адресной строки. API принимает токен в заголовке `x-owner-token`, а не в URL.

## Музыка и хранение

Есть шесть встроенных синтезированных мелодий. Свои файлы до 15 МБ загружаются в Supabase Storage (`shaqyru-audio`), а не на временный диск сервера. Старые `/uploads/` сохранены для совместимости; при переносе проекта их необходимо перенести вместе с сайтом. Новая загрузка требует секрет владельца и проверяет формат и сигнатуру аудио.

`npm run audio:cleanup` только показывает количество неиспользуемых загруженных файлов старше семи дней. `npm run audio:cleanup -- --apply` удаляет такие файлы после повторной проверки ссылок в базе. Запускайте удаление в период, когда пользователи не сохраняют приглашения. Настройка расписания выполняется отдельно на хостинге.

## Безопасность и размещение

- В старом `.env.example` были значения, похожие на настоящие ключи. Если они действующие, замените их в Supabase / настройках администратора. Удаление из примера не отзывает ранее раскрытый ключ. Проверьте также старый ZIP в `backup`: архивы могут содержать прежние секреты.
- Для `/admin` задайте длинный случайный `ADMIN_KEY`; страница показывает только проверенный статус оплаты.
- Настройте резервное копирование Supabase. Резервные архивы и `.env` исключены из Git и Docker-сборки.
- `TRUST_PROXY_HOPS=1` используйте только за одним доверенным reverse proxy. По умолчанию — `0`.
- Ограничение запросов хранится в памяти одного процесса. Для нескольких экземпляров приложения нужен общий лимитер.
- Не включайте логирование тел запросов и заголовков с секретами в reverse proxy.

## Календарь, гости и приватность

- На странице гостя и в предпросмотре есть скачивание `.ics` для календаря телефона. Укажите часовой пояс мероприятия; при отсутствии времени событие сохраняется на весь день. Обратный отсчёт также использует этот часовой пояс.
- Кнопки 2ГИС и Google Maps используют адрес. Необязательные широта и долгота позволяют указать точное место; Google Maps открывает построение маршрута.
- В разделе гостей доступны комментарии, поиск по имени/комментарию, фильтр ответов и CSV для Excel. Выгружаются строки, соответствующие текущему поиску и фильтру, в UTF-8 с BOM.
- В раскрываемом блоке «Доступ и приватность» устанавливается пароль для гостей. Пароль хранится на сервере только как scrypt-хеш с солью и не попадает в черновик браузера или гостевой ответ API. Гостевой доступ действует 12 часов в текущей вкладке; смена пароля отзывает старые токены. Пароль не заменяет подтверждение оплаты.
- Можно закрыть приглашение вручную или в заданное время в часовом поясе мероприятия. Закрываются просмотр и ответы гостей; владелец сохраняет доступ к редактированию и предпросмотру. Для открытия снимите галочку и удалите срок закрытия.
- Для публичных оплаченных приглашений сервер выдаёт метаданные и PNG-обложку ссылки с именами, датой и местом. Нужен доступный извне HTTPS-сайт и `PUBLIC_URL`. Локальный адрес недоступен WhatsApp. Неоплаченные, закрытые и защищённые паролем приглашения не раскрывают персональные данные в обложке. Мессенджер может хранить ранее полученную обложку в своём кеше.

Дополнительная миграция для этих настроек не требуется: они сохраняются в существующем JSON приглашения. Миграция оплаты из раздела выше по-прежнему нужна для работы гостевых ссылок.

## Проверка

`npm run check` — проверка синтаксиса серверных файлов, браузерных модулей и встроенных скриптов страниц.

`npm test` — проверки оплаты, контроля доступа и входных данных, без реального списания денег и без обращения к рабочей базе.

`npx playwright install chromium`, затем `npm run test:browser` — предпросмотр на компьютере и телефоне, все дизайны и анимации, сохранение, отказ доступа гостям и отключённая оплата.

Автоматические тесты используют локальные подмены ответов. Они не заменяют проверку миграции в Supabase и оплаты с рабочим кабинетом продавца.

## Безопасное сохранение и оптимизация

Изменения приглашения и пароля используют версию документа и условное обновление существующего JSON в Supabase. Если другая вкладка уже сохранила новую версию, сервер возвращает 409: редактор сохраняет локальные правки и предлагает скачать черновик или загрузить актуальный документ. Перед загрузкой актуального документа текущий черновик сохраняется в `shq-recovery` в этом браузере. Новая миграция для контроля версий не требуется. Клиенты API должны передавать `version`, полученную при создании, проверке статуса или предыдущем обновлении. Старый клиент без версии не может перезаписать уже версионированный документ.

Повторная отправка ответа по общей ссылке использует стабильный идентификатор запроса и обновляет существующую запись. Это предотвращает дубли при повторной отправке из того же браузера с тем же именем; это не проверка личности гостя на других устройствах.

Оригиналы обложек сохранены. Сайт использует WebP и небольшие превью с отложенной загрузкой. После добавления обложек выполните `npm run assets:build`. Необязательная миграция `migrations/002_guest_index.sql` добавляет индекс для списка гостей; применяйте её отдельно после проверки в тестовой базе.

Мобильные поля рассчитаны на ширину от 320 пикселей. Приглашение растёт по высоте для длинного текста. Системная настройка уменьшения движения отключает эффекты CSS и canvas; музыка и вступительный экран доступны с клавиатуры.

Файл `MODERNIZATION_REPORT.md` описывает выполненные изменения, проверки и оставшиеся задачи перед рабочим запуском.

## Помощь при создании приглашения

Кнопка «Создать пошагово» включает четыре этапа: повод, дизайн, данные и оформление, проверка. «Показать все настройки» возвращает привычный редактор без потери изменений. Проверка напоминает об отсутствующих именах, дате, времени, месте, тексте и адресе либо координатах; прошедшая дата сопровождается предупреждением. Подсказка переводит к соответствующему полю. Проверка не запрещает сохранять черновик и не заменяет проверку оплаты.

Фотографии JPEG, PNG и WebP до 15 МБ можно кадрировать с увеличением, сдвигом и поворотом на 90°. Максимум — 40 миллионов пикселей. Обработка выполняется в браузере: оригинал не отправляется на сервер. В приглашение сохраняется только подготовленный JPEG 360×480. Отмена и ошибка чтения оставляют прежнюю фотографию.

## Единый праздничный дизайн

В разделе 5 редактора доступно отдельное фото заставки (JPEG, PNG, WebP до 12 МБ), положение кадра по двум осям и удаление фото. Изображение обрабатывается локально до 1200 px по длинной стороне; подготовленный JPEG сохраняется вместе с приглашением. Фото внутри карточки остаётся независимым. Добавлены восемь фотосцен: киноистория, альбом, диафрагма, мозаика, стопка снимков, цветочное раскрытие, панорама и растворение. Всего 16 способов открытия и автоматический подбор, с фильтрами по категориям. Общая реализация в `public/opening-scenes.js` и `public/opening-scenes.css` используется редактором, гостевой страницей и демонстрацией `/invitation-motion.html`. Демонстрация хранит свои настройки отдельно от рабочего черновика.

Уменьшение движения учитывается автоматически. В ручном просмотре фотосцен можно явно включить движение; Escape или «Пропустить» закрывает сцену. Проверки новых возможностей: `tests/browser/openings.spec.js`, `tests/browser/motion.spec.js`, `tests/openings.test.js`.

Главная `/` представляет сервис в утверждённом светлом стиле: коралловые и голубые акценты, праздничные фотографии, коллекция событий, описание возможностей и ответы на вопросы. Создание приглашений вынесено на отдельную страницу `/create`. Переключатель трёх вариантов оформления удалён; старые ссылки `?design=studio`, `?design=evening` и `?design=heritage` показывают единую главную.

Главная и редактор доступны на русском и казахском. Выбор языка переносится через ссылку в редактор. Выбор категории на главной задаёт повод только для нового черновика; сохранённое приглашение открывается без замены его повода и оформления. Старые ссылки владельца `/#id=ID&t=ТОКЕН` и возврат оплаты `/?payment=return` переводятся в редактор. После чтения секрет владельца удаляется из адресной строки.

Общие стили: `public/brand.css`. Главная: `public/index.html`, `public/home.css`, `public/home.js`. Редактор: `public/create.html`, `public/studio.css`, `public/studio.js`. Панели гостевой страницы: `public/guest.css`; индивидуальное оформление самих приглашений сохраняется. Окна оплаты, гостей, фото и страница администратора используют общую палитру.

Изображения созданы встроенным ImageGen и сохранены в `public/images/`; для сайта используются WebP общей величиной около 474 КиБ. Исходные PNG сохранены рядом. Направление и происхождение изображений описаны в `.design/approved-style.md`.

Проверено: `npm run check`, `npm test` (22 теста), все 35 браузерных тестов (Chromium). Проверки включают ширины 320, 390, 768, 1024, 1440 px, клавиатуру, уменьшение движения, новый маршрут, старые ссылки, языки и сохранность черновика. Рабочая оплата и база не использовались: серверные ответы в соответствующих тестах подменяются. Проверка экранным диктором и в Safari не проводилась.


### Живая страница, история и библиотека приглашений

В разделе 5 редактора добавлены четыре сцены для всей гостевой страницы: цветущий сад, звёзды, шары и орнамент. Скорость и плотность настраиваются отдельно; доступны спокойный и праздничный режимы. Движение приостанавливается в скрытой вкладке, учитывает системное уменьшение движения и отключается кнопкой на гостевой странице.

История содержит до пяти JPEG/PNG/WebP с подписями и изменяемым порядком. Загрузки сжимаются; суммарный размер фото истории ограничен 2,2 млн символов, чтобы оставить место текущему черновику. На гостевой странице доступны ручное переключение и слайд-шоу по запросу. Сервер очищает новые поля перед сохранением.

Быстрые ссылки ведут к ответу гостя, маршруту и календарю. Ошибка RSVP остаётся видимой до повторной попытки; подтверждение доступно с клавиатуры.

Страница /library.html («Мои приглашения» в редакторе) хранит несколько черновиков в IndexedDB этого браузера. Переход /create?draft=KEY открывает выбранную запись. Копирование не переносит серверный ID, токен владельца, оплату, версию документа и закрытие доступа. Ответы гостей загружаются только по запросу владельца с его токеном. Это локальная библиотека, не облачный аккаунт; очистка данных браузера удаляет её.

Проверки обновления: 24 серверных теста, 35 браузерных сценариев (celebration, library, openings, invitations, quality и features), проверка синтаксиса. Серверные ответы в браузерных сценариях подменяются; реальная база и оплата не проверялись. Ручной визуальный просмотр обновления во встроенном браузере заблокирован лимитом автоматической проверки разрешений.


### Полный предпросмотр, дополнительные сведения и аккаунт

Новый этап: история изменений с отменой/повтором, шаблон личного обращения, расширенные ответы гостей, видеоэкспорт и совместные ссылки просмотра/редактирования. Подробности, ограничения видео и подключение дополнительных ответов: [EDITOR_UPGRADES.md](EDITOR_UPGRADES.md). Новые поля ответов требуют миграции `004_rsvp_details.sql`; совместные ссылки используют существующую таблицу приглашений.

В разделе «Интро» есть поиск анимаций по названию и описанию на обоих языках, фильтр избранного и личный список вариантов. Избранное хранится отдельно от приглашения в этом браузере. В раскрываемом списке кнопка «Смотреть» показывает вариант с текущим фото без изменения черновика, «Выбрать» применяет его, «Убрать» удаляет только из списка. Категории, все существующие анимации и обычный выбор карточкой сохранены. Проверки: `tests/browser/animation-tools.spec.js` и `tests/browser/openings.spec.js`.

Редактор сохраняет прежний режим карточки и добавляет переключатель «Вся страница». Телефонный предпросмотр работает в боковой панели, компьютерный — в большом модальном окне. Оба используют ту же гостевую страницу /preview, без отправки ответов от имени реальных гостей. Изменения обновляются с задержкой 500 мс; повторное сохранение тех же данных не перезагружает страницу. Встраивание разрешено только для /preview и только с того же origin.

Фото истории сохраняют индивидуальные положение, масштаб (1–2), способ кадрирования и время показа (3–15 секунд). Исходное сжатое изображение сохраняется, поэтому кадрирование можно менять. Предпросмотр и гостевой кадр имеют пропорцию 4:5. Слайд-шоу запускается пользователем и останавливается при скрытии вкладки.

Три готовых сочетания меняют только палитру, шрифт, рамку и эффекты; предусмотрена отмена последнего применения. Все 30 существующих дизайнов и прежние эффекты остаются доступны. Блок «Гостям» содержит дресс-код с палитрой, пожелания по подаркам, контакт организатора и до шести вопросов. Пустые блоки скрыты. Секции гостевой страницы плавно появляются при прокрутке с учётом уменьшения движения.

Аккаунт использует Supabase Auth: вход по email-коду, сессия в HttpOnly cookies, обновление сессии и выход. Облачные черновики доступны только владельцу; сервер проверяет версию перед записью и исходный owner token при сохранении опубликованного приглашения. Локальные черновики и прежний доступ по ссылке владельца сохраняются. Подробное подключение: [ACCOUNT_SETUP.md](ACCOUNT_SETUP.md). Реальный вход и межустройственная синхронизация требуют миграции 003, публичного ключа Auth, PUBLIC_URL и настройки email-кода/SMTP. Они пока не включены в локальном окружении.

Проверки нового этапа: 27 серверных тестов; браузерные сценарии account, experience, assistant и регрессии quality, openings, invitations, features, celebration, library. Новые сценарии проверяют встроенный просмотр, мобильное окно, Escape/фокус, настройки фото, сохранность контента при применении сочетаний, вход/выход и облачное сохранение на подменённых ответах. Проверены также конфликт между вкладками библиотеки и сохранность местных правок после остановки автосинхронизации при конфликте. Для проверки реального подключения без изменений базы и отправки писем используйте `npm run account:check`; подробности — в `ACCOUNT_SETUP.md`. Ручная визуальная проверка во встроенном браузере остаётся недоступной после отказа автоматической проверки разрешений из-за лимита использования.
